# CreatorComposerPosition performance guard

| Area               | Verdict | Evidence                                                                                                                | Change or reason kept                                                                           | Verification                                                                         |
| ------------------ | ------- | ----------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------ |
| Background work    | keep    | A shared scalar preference drives component rendering; geometry uses CSS auto margins                                   | No added polling, scans, retries, workers, process launches, or global listeners                | Source trace and focused suites                                                      |
| Memory             | keep    | One `creatorComposerPositionAtom` replaces the ChatPanel-local atom; editor ancestry is unchanged                       | No duplicate input, growing cache, or copied draft store                                        | Regression asserts exact DOM node identity and edited values across both transitions |
| Scope/isolation    | keep    | SessionCreator, CreatorContentLayout, organization and GitHub forms, and the menu read the same atom                    | Store contains only local UI placement; no identity, organization, or session data enters it    | Shared-consumer integration test and entry-point audit                               |
| Rendering/hot path | keep    | Mounted creator owners subscribe to input and/or resolved trail scalars; layout changes only on user preference updates | No viewport polling or frame-by-frame state work; fill-sized frames delegate to agent composers | Lint and focused tests; direct desktop CPU/RSS not measured                          |

Lifecycle review: startup reads the existing saved scalar through atom storage; idle and hidden creators gain no recurring work; changing input or trail position preserves existing input nodes; the trail atom reads input placement only when no explicit override exists; unmount removes component subscriptions. Switching between card and pill locations retains the existing attachment generation/source-data cleanup; only one Solve Work Item control is mounted in either layout. Required runner and form controls remain mounted. Network, auth, provider ingestion, and multi-instance transport are unchanged.

The trail default is a synchronous derived read over the existing saved preference and input position. The linked input change action clears the saved trail override in the same synchronous state update; no effect copies defaults to storage, no second trail preference is created, and no timer, network request, or app-lifetime collection is added. The existing atom storage subscription is shared by mounted consumers and released on unmount. Agent native menus and the new header switch write the same owner. Manual creators keep their existing skills/actions row above the editor and remove the trail subscription. The Agent view renders its existing actions row once above the composer in every layout. No new state, timer, or listener is introduced.

Additional trail verification: seven state tests cover automatic defaults, resetting saved overrides in both directions, later manual overrides, reselecting the current layout, persistence/hydration, and malformed values. A mounted manual-composer test verifies skills/actions remain above title and description nodes/edited values as input/trail settings change in Work Item and Project simultaneously. Existing repo-row menu and spacing/glow suites passed.

The isolated integration branch reruns full TypeScript, creator/trail tests, modal lifecycle tests, circular-dependency checking, and test placement; exact outcomes are recorded in the PR and CreatorRefactorStack.md. No polling, worker, or data cache is added for layout preferences. Existing storage keys and values are preserved; changing layout clears only the explicit trail override.

Performance verdict: **blocked** for native Tauri CPU/RSS measurements, which require Computer Use authorization. Unit-level lifecycle and draft-continuity evidence is available; no measured performance improvement is claimed.
