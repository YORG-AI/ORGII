# BranchPicker UI audit

Scope: session and local branch switching, in Spotlight and compact dropdown presentations. The tab label remains `PR`; `Pull requests` stays English within localized surrounding copy. Visible search placeholders end in `...`. No repository name appears in the picker chrome.

PR branch details are hidden by default. The shared “Show branch info” checkbox appears inside the lower keyboard-hint pill, matching “Show path”; the compact presentation exposes the same control in its footer. PR numbers and authors remain visible, branch details follow the author, and hidden branch names remain searchable. Check status appears at the right edge regardless of this preference.

Verdict totals: **0 fix**, **11 keep with reason**, **0 abstract**.

Automated DOM checks use production virtualizers, rows, and keyboard hooks with jsdom viewport geometry. They cover 10,000 branches, 10,000 mixed Spotlight rows, PR pagination, filtering, cancellation, footer navigation, and icon semantics. Shell positioning is mocked; CSS pixels, native themes/viewports, and Tauri screenshots were not inspected. Computer Use is explicitly opt-in and was not requested. No visual pass is claimed.

The preference checks additionally use the production footer portal and checkbox. They verify lower-pill placement, default-off behavior, saved on/off values across fresh stores, hidden-branch search, no requests on toggle, bounded mounted rows, and safe keyboard handling with a highlighted PR.

Color reference: [GitHub Primer colors](https://primer.style/product/primitives/color/) and `@primer/primitives` 11.10.0 light/dark theme CSS. The dark attention/success/danger/muted tokens were also verified against the published 11.10.0 dark theme CSS. No new dependency was installed.

Check-status DOM tests cover all five states in both presentations, right-edge placement, icon-only accessible labels, and one list request after rendering and filtering.
