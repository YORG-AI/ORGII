# ORG2 Remote iOS shell architecture

**Date:** 2026-09-02
**Scope:** PR2 — an independent, lightweight Tauri iOS shell that reuses Web
Remote's product root while keeping the agent runtime on the paired Desktop.

This document records the minimum architecture that can be implemented and
verified in this PR. It does not claim that Universal Links, a server-side
multi-desktop inventory, background relay sockets, push notifications, or an
offline transcript database already exist.

## Decision

The iOS app is a sibling Tauri product, not a mobile build of the Desktop
binary. Its bundle identifier is `org2ai.org2.remote`; its Rust graph owns only
the WebView, system-browser handoff, deep-link delivery, and narrowly scoped
Keychain access. The Desktop continues to own and run the agent, session
EventStore, tools, terminals, repositories, and relay administration.

The shared product root is `MobileRemoteRoot`:

```text
MobileRemoteRoot
  -> MobileAuthGate
  -> MobileRemoteApp
       -> MobileRemoteProviders
       -> existing transcript / interaction / navigation UI
```

The native shell must inject a `MobileRemotePlatform`; it must not copy the
auth, pairing, connection, transcript, or chat state machines into a parallel
native screen. A native-only screen is justified only for behavior absent from
the shared product, and must be reached from a production entry point.

## Acceptance criteria for this PR

- `apps/remote-ios/src-tauri` is an independent crate and does not depend on
  the Desktop `src-tauri` crate or any Desktop runtime crate.
- the Rust library exports a mobile entry point and the three required crate
  types: `staticlib`, `cdylib`, and `rlib`;
- the Tauri identifier is exactly `org2ai.org2.remote` and the generated iOS
  target is signed for that registered identifier;
- the native webpack graph starts at `mobileRemoteNativeEntry.tsx`, reaches
  `MobileRemoteRoot`, and cannot reach the Desktop entry or browser adapter;
- cold-start and warm `org2remote://auth/callback` delivery both notify the
  auth state machine, while malformed/replayed callbacks fail closed;
- GitHub/Supabase OAuth opens in the system browser, PKCE/session secrets and
  pairing credentials are stored in Keychain, and raw secrets or callback
  URLs are never logged;
- the current WebSocket and relay JSON-RPC wire contract is reused without a
  native agent runtime or a second transcript store;
- the UI describes the account-scoped local Keychain inventory and its one
  active Desktop honestly; it does not present that inventory as a server-side
  account-authoritative paired-device list;
- build output, capabilities, CSP, opener allowlists, and generated artifacts
  are scoped to the iOS product;
- TypeScript adapter tests, Rust boundary tests, simulator tests, and at least
  one real-device OAuth return/pairing flow provide evidence before the PR is
  marked ready.

## Minimal file, dependency, and entry topology

```text
apps/remote-ios/
  src-tauri/
    Cargo.toml
    Cargo.lock
    build.rs
    tauri.conf.json
    Info.ios.plist                   # org2remote custom URL scheme
    capabilities/mobile.json
    src/
      lib.rs                         # #[cfg_attr(mobile, tauri::mobile_entry_point)]
      main.rs                        # optional desktop development shim
    gen/apple/                       # generated by `tauri ios init`, never hand-authored

src/mobileRemoteNativeEntry.tsx
src/modules/MobileRemote/platform/tauri/
  tauriMobileRemotePlatform.ts       # production + injected factories
  tauriMobileAuthClient.ts           # shared PKCE + Keychain storage adapter
  tests...
src/modules/MobileRemote/connection/
  mobilePairedDesktopInventory.ts    # bounded local inventory projection
```

The implemented Rust dependency set is Tauri, `tauri-plugin-deep-link`,
`tauri-plugin-opener`, `serde_json`, and Apple's `security-framework` /
`security-framework-sys`. It deliberately does not use
`tauri-plugin-keychain`. Repository-owned Tauri commands fix the service to
`org2ai.org2.remote`, accept only three exact keys or the owned PKCE/inventory
prefixes, bound key length to 512 bytes and value length to 64 KiB, and return
stable error codes without secret values. No shell, filesystem, updater,
terminal, PTY, Git, database, LSP, browser automation, agent-core, or Desktop
settings dependency is present.

Native and Desktop production builds are isolated. Native webpack emits only
`mobileNative` into `build-mobile-native`; Desktop/Web continue to emit into
`build`. The Tauri `frontendDist` points to the native directory, and both the
native output and native Cargo `target/` are ignored.

```text
  -X-> Desktop app crate / agent-core / EventStore / PTY / Git / LSP / DB
```

Static import-boundary tests should enforce both negative edges. Runtime
comments or separate webpack entries alone are not evidence of isolation.

## Authoritative data and ownership

| Concern                                           | Authoritative source                                           | Local projection/owner                                                                                | Required invariant                                                                                        |
| ------------------------------------------------- | -------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------- |
| Account authentication                            | Supabase/ORG2 Cloud                                            | `MobileAuthGate`; encrypted session in Keychain                                                       | one user-scoped session; refresh-token writes finish before state advances                                |
| OAuth attempt / PKCE verifier                     | the attempt and verifier created by the shared Supabase client | 10-minute single-use attempt marker plus Supabase-owned verifier under an allowlisted Keychain prefix | callback exchange is rejected when the attempt is absent/expired; Supabase consumes the matching verifier |
| OAuth callback intent                             | iOS deep-link delivery                                         | ephemeral native driver + auth notification                                                           | exact scheme/host/path validation; consume once; never log raw URL                                        |
| Pairing approval, tier, and revocation            | relay/Desktop                                                  | opaque pairing intent and device token in Keychain                                                    | account login does not grant relay access; device token remains the relay credential                      |
| Active Desktop connection                         | the selected local inventory entry plus live relay handshake   | `MobileRemoteProviders`                                                                               | one active config with serialized writes and generation-guarded bootstrap                                 |
| Locally retained paired Desktops                  | Keychain inventory scoped by encoded Cloud user id             | versioned inventory, capped at 20 entries; UI receives credential-free summaries                      | useful local history/selection, but not proof of current server pairing or revocation state               |
| Server-side account-wide paired Desktop inventory | **not available in the current protocol**                      | none                                                                                                  | do not present the local inventory as a complete server-backed list                                       |
| Transcript, rounds, events, and tools             | Desktop EventStore                                             | disposable shared reducers                                                                            | the phone never becomes a second transcript database                                                      |
| Active socket                                     | current foreground provider generation                         | provider ref only                                                                                     | release when hidden; stale sockets cannot mutate a newer generation                                       |

### Relay permission boundary

The relay endpoints for completing pairing, listing devices, revoking devices,
and selecting a primary Desktop are Desktop-admin operations authenticated by
the Desktop token. The mobile device token authorizes the paired mobile socket;
the Cloud access token authenticates the ORG2 account. These credentials are
not interchangeable.

The connection port now stores a versioned, account-scoped Keychain inventory,
exposes credential-free summaries, and lets the user select one active Desktop.
Parsing rejects unsupported versions and malformed rows, selection must match
an existing id, and both parsing and insertion cap retained entries at 20. This
is a truthful local history of pairings made on this phone, but it can be stale
after remote revocation and cannot discover pairings made elsewhere.

A complete server-backed device list, remote revoke, or account-wide primary
Desktop requires a separately designed Cloud/relay API, authorization model,
pagination, reconciliation, and tests. That API is a later feature; local
inventory support does not remove the relay permission boundary.

## OAuth, deep-link, and Keychain lifecycle

The canonical first-release callback is
`org2remote://auth/callback`. Configure it under the Tauri mobile deep-link
plugin and the Supabase redirect allowlist. OAuth must use `openUrl` in the
system browser; do not use an embedded auth WebView.

Cold and warm delivery are separate entry paths and must converge:

```text
cold launch
  -> register onOpenUrl listener
  -> await getCurrent()
  -> validate + capture callback/pairing intent
  -> create platform
  -> mount MobileRemoteRoot

warm callback
  -> onOpenUrl(urls)
  -> validate + capture exactly one supported URL
  -> notify MobileAuthGate/auth coordinator
  -> authenticate() performs single-use attempt check and exchange
```

The production adapter now registers `onOpenUrl` before awaiting `getCurrent`,
validates only exact `org2remote://auth/callback` and
`org2remote://pair` intents, and publishes `auth_callback` / `pairing` events
through `subscribeIntent`. `MobileAuthGate` invalidates any older auth episode,
waits for pending auth/sign-out work, and re-authenticates from the newest
intent. The adapter deduplicates at most 16 recent URLs for 60 seconds, retains
intents for at most 10 minutes, and removes the native listener on `pagehide`.
Thus cold and warm delivery converge without remounting or refreshing.

The shared reducer uses `checking`, `signed_out`, `redirecting`, `exchanging`,
`signed_in`, and `error`; in-flight authentication and sign-out cleanup are
separate guarded lifecycle operations rather than duplicate presentation
states. Every async result is guarded by the active auth generation. Preserve
the existing invariants:

- rotated session storage completes before auth state advances;
- post-write generation checks reject stale auth completion;
- sign-out waits for pending authentication before final cleanup;
- a subsequent sign-in waits for that cleanup;
- malformed, wrong-origin, fragmented, missing-code, missing-attempt, expired,
  and replayed callbacks fail closed.

The shared Supabase PKCE client makes browser server-session establishment an
explicit option. Browser Remote retains relative `/v1/mobile/auth/session` and
its cookie contract. Tauri iOS deliberately passes `serverSessionUrl: null`:
its authority is the Supabase session plus the paired Desktop device
credential, so it neither depends on nor silently attempts a same-origin
browser cookie exchange from the custom-protocol WebView.

Universal Links are a later compatibility enhancement. Do not claim them until
an owned HTTPS domain serves a valid AASA file containing the Apple team ID,
`org2ai.org2.remote`, and the exact callback path, and both installed-app and
browser fallback paths have been tested.

## State, error, compatibility, and lifecycle boundaries

| Boundary                      | Required behavior                                                                                                                                             |
| ----------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Auth race                     | auth generation rejects late restore/exchange/write completion; callback is single-use                                                                        |
| Connection race               | provider and adapter serialize writes; bootstrap/load/socket callbacks check generation                                                                       |
| Hidden/background             | cancel reconnect timers and close the foreground socket; do not promise background agent execution                                                            |
| Foreground                    | revalidate auth and reconnect only the retained active config when no current socket owns the generation                                                      |
| Keychain locked/unavailable   | typed, user-visible recoverable error; never fall back to localStorage or plaintext                                                                           |
| Pairing expired/revoked       | typed pairing/authorization error; preserve account login, clear only invalid connection material                                                             |
| Network loss                  | bounded retry while visible; retained Desktop/EventStore remains authoritative                                                                                |
| OAuth cancel/invalid callback | return to signed-out or typed error state without consuming unrelated pairing data                                                                            |
| Upgrade                       | version and validate stored envelopes; reject unknown versions rather than casting arbitrary JSON                                                             |
| Sign-out/account switch       | clear auth session and pending intents in an ordered final write; keep inventories isolated by user id and load only the newly authenticated user's inventory |
| Reinstall                     | explicitly verify the chosen Security.framework persistence behavior on a signed device                                                                       |

The relay wire remains JSON-RPC 2.0 over WebSocket, protocol version `1`. The
iOS adapter supplies client identity and socket construction only; it does not
rename methods, reinterpret tool events, or change `session/send`, round, or
interaction payloads. The same provider continues to enforce serialized
connection persistence, bootstrap/load generation guards, hidden-socket
release, and stale-socket ownership guards.

## Initialization parity

| Step                                       | Browser entry                    | iOS entry                                        | Test entry                      |
| ------------------------------------------ | -------------------------------- | ------------------------------------------------ | ------------------------------- |
| Capture pairing/callback before auth mount | synchronous URL capture          | listener registered, then `getCurrent()` awaited | seeded driver                   |
| Build platform                             | browser singleton                | awaited native bridge/platform                   | explicit fake                   |
| Initialize i18n                            | awaited                          | awaited                                          | explicit provider               |
| Mount shared root                          | `MobileRemoteRoot`               | `MobileRemoteRoot`                               | same root for integration tests |
| Handle warm callback                       | browser navigation reloads entry | `onOpenUrl` notifies mounted auth owner          | emit callback after mount       |
| Revalidate on foreground                   | visibility event                 | app/WebView lifecycle event                      | deterministic runtime fake      |
| Cleanup                                    | document listener/socket cleanup | deep-link unlisten + timers/socket cleanup       | assert disposer calls           |

The iOS bootstrap must not render until platform creation, cold URL capture,
and i18n initialization either complete or enter an explicit startup-error
state. An empty WebView is not a loading state.

## Resolver symmetry

| Value             | Primary source                                       | Retained source                | Finalization                                                                                                 |
| ----------------- | ---------------------------------------------------- | ------------------------------ | ------------------------------------------------------------------------------------------------------------ |
| Auth session      | callback exchange                                    | Keychain session refresh       | durable write -> generation check -> signed-in transition; browser alone also establishes its cookie session |
| Pairing intent    | cold/warm deep link                                  | TTL-bound Keychain intent      | consume only after signed-in account is established                                                          |
| Active connection | freshly approved pairing or explicit local selection | user-scoped Keychain inventory | serialized inventory save -> connect with active generation                                                  |
| Transcript        | live Desktop notification                            | Desktop round/history RPC      | stable-ID reducer reconciliation only                                                                        |

No resolver may use localStorage as a native fallback. Callback and restored
sessions must converge on the same finalization chain; freshly paired and
restored connections must converge on the same provider connect path.

## Ten-layer architecture audit

| Layer                        | Findings and required disposition                                                                                                                                                                                                                                                                                                                                                                    |
| ---------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1. Compilation correctness   | The production entry awaits the zero-argument Tauri factory, which constructs the real invoke/deep-link/opener bridge and returns `MobileRemotePlatform`. `pnpm typecheck`, host `cargo check`, and the two Rust boundary tests pass; the independent crate has the correct mobile crate types and entry annotation. iPhoneOS SDK, signed iOS build, simulator, and device evidence remain required. |
| 2. Dead code and duplication | The earlier parallel native access screen is absent. Production mounts `MobileRemoteRoot`; native code supplies environment ports rather than a second auth/device/chat FSM.                                                                                                                                                                                                                         |
| 3. Naming consistency        | Use `ios`, `native`, `browser`, `Desktop`, `deviceToken`, and `desktopToken` consistently. `bridge` means the narrow Tauri adapter here, not the Desktop mobile-relay bridge.                                                                                                                                                                                                                        |
| 4. Semantic overloading      | “paired devices” remains two concepts: bounded account-scoped local history vs Relay admin inventory. “Session” is Cloud auth session vs Desktop agent session. Types and copy identify the local inventory and active selection explicitly.                                                                                                                                                         |
| 5. Default branches          | Reject unknown stored versions, auth callback origins, error codes, and protocol capabilities. Do not default unknown Keychain errors to network retry, or unknown URLs to accepted callbacks.                                                                                                                                                                                                       |
| 6. Cross-domain leakage      | The iOS Rust crate must not import Desktop agent/runtime crates; shared TS must not import Tauri or browser adapters. Native credentials/navigation stay behind the platform port.                                                                                                                                                                                                                   |
| 7. New-developer clarity     | The sibling crate and import diagrams make it explicit that the agent runs locally on Desktop, not on the iPhone. Comments must not imply Cloud login grants relay administration.                                                                                                                                                                                                                   |
| 8. Wire and serialization    | Relay JSON-RPC remains unchanged. Native OAuth intentionally has no browser server-session request. Tests must assert callback validation, `initialize`, pairing payload, `session/send`, versioned inventory envelopes, and sanitized summaries; never inspect only source types.                                                                                                                   |
| 9. Initialization parity     | Browser and iOS both capture initial intent before auth/root initialization. iOS registers warm delivery before cold `getCurrent`, then both paths publish through the same intent port.                                                                                                                                                                                                             |
| 10. Resolver symmetry        | Callback/restore auth paths converge on Keychain persistence and generation guards; fresh/restored/selected connections converge on the same provider connect path. Browser-only cookie session establishment is an explicit shell capability, not an accidental fallback.                                                                                                                           |

## Current hard risks and staging

### Must be resolved before this PR is ready

1. **Apple build and device evidence:** full Xcode/iPhoneOS SDK selection,
   bundle signing for `org2ai.org2.remote`, simulator launch, and a real-iPhone
   cold/warm OAuth plus pairing flow remain unverified.
2. **External OAuth configuration:** Supabase must allow
   `org2remote://auth/callback`. The repository can configure and validate the
   app callback, but cannot prove the external redirect allowlist from source.
3. **Dynamic relay CSP:** opener permissions are narrowed to the official
   Supabase and ORG2 Cloud origins, and Keychain commands are allowlisted. Relay
   endpoints are user-configurable, however, so `connect-src` intentionally
   retains `wss:`. This broader network surface is a conscious compatibility
   risk; pairing URL validation and per-Desktop device credentials remain the
   authorization boundary.

### Explicitly later; this PR must not claim them

- a server-authoritative account-wide multi-Desktop list, primary Desktop
  mutation, or remote revoke action available to the phone (the local bounded
  inventory and active switching already exist);
- Universal Links and browser fallback;
- background/always-on relay connection or local agent execution;
- APNs, offline transcript/action queue, or a native transcript database.
