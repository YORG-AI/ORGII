# Workstation sidebar surface ownership

## Acceptance criteria and result

The change addresses the sidebar ownership finding: project navigation and work-item maps must no longer travel through session menu decoration, and extracting files must establish an owner rather than another universal argument bag. There is no intended user-experience change.

- The connector falls from 896 to 669 lines. Organization scope, cross-surface reveal/selection, shared navigation, and rendering remain there.
- `useWorkItemsSidebarSurface` accepts six inputs and owns its menu source, local selection, per-group page counts, collapsed sections, row clicks, and hover renderer. Its maps and mapping functions no longer escape into session decoration or chrome.
- `useSessionSidebarRowActions` replaces the 44-input mixed decoration hook with 19 session-only inputs; it owns active more-menu state and existing move/share/sync dialogs. The session model now calls `useSessionMenuItems` directly; the forwarding-only mixed session/project builder is deleted.
- `useChannelsSidebarSurface` owns cloud/local channel composition, click claims, selection precedence, and dialog outputs. Both underlying controllers remain unconditionally mounted with their original scope gates.
- `useSidebarGuide` owns guide progress reads/writes, request IDs, and actions. The existing guide button stays in the same place; hiding/dismissing it does not unmount its state.
- `useSidebarStationNavigation` names the shared route-entry behavior used by session and work-item actions. Shared selection precedence and session collapse handling remain explicit in `sidebarConnector.selectionAndCollapse`.

This deliberately does not change the underlying data loaders, stores, menu rows, permissions, pagination sizes, reveal hydration, draft promotion, sidebar memory, styling, or native-menu behavior. A new universal context or a conditional surface component would weaken lifetime parity and is not introduced.

## Behavior review

The full diff was read against the base. Token-stream comparisons (ignoring formatting/comments) confirmed that 24 moved/preserved callback or initializer bodies are identical: guide actions/scope label, shared station-entry callbacks, selection precedence, session/project collapse handlers, project click wiring, session dialog/context/action decoration, and cross-surface click routing. Guide completion changes only the input name from `sessions.length` to `sessionCount`.

The JSX hierarchy, keys, labels, icons, styles, loading UI, host-specific organization-selector placement, dialog order, and wrapper implementations are unchanged. `SidebarGuideButton` receives the same props through the guide result. No conditional mount, new timer, new request, cache, global state, dependency, or lockfile is added.

The new hook tests run the real work-item click router and state owner while mocking the data source and outgoing tab atoms. They check per-group collapse resets, page counts and selection retained across view/scope switches, local/project/work-item/Linear routing, linked-session row keys, and organization-scoped creation. Channel ownership tests assert both controller lifetimes, scope gates, fallback/selection, dialog outputs and click-claim order. Existing real channel-dialog tests retain close/reopen drafts within an org and reset/close them on org switches. Routing tests protect drafts/New conversation before the work-item route, modifier clicks, and Team Inbox in the legacy projects scope.

Performance verdict: **blocked for real-app measurement**. Automated lifecycle checks and structural review provide refactor-parity evidence, but visible/hidden idle CPU/RSS, native menus, network disconnect/reconnect, auth/endpoint changes, restart and multi-instance behavior were not exercised. Computer Use is explicitly opt-in and was not authorized; no desktop-control API was invoked. This does not assert a measured performance regression or improvement. Provider ingestion and transport are unchanged and no provider/topology coverage claim is made.
