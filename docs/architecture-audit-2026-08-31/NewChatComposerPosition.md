# CreatorComposerPosition architecture review

Acceptance criteria: one saved Bottom/Middle preference across every creation surface; Bottom retains established layouts; Middle centers creator inputs and places existing suggestion actions at the bottom as compact pills; compact controls match the provided sidebar Layout screenshot; switching does not discard drafts; a shared Up/Down Trail preference automatically resets to Up for Bottom and Down for Middle on each input-layout change; the skills/actions row stays Up in both Agent and Manual independently of those preferences.

The earlier implementation passed the preference only to the single-session start-page launcher. Embedded agent creators did not receive it, and manual creators used a separate layout owner. The fix moves the authoritative preference to shared creator state, removes the optional host-prop path, and connects every layout owner to that same atom.

| Layer                  | Coverage and conclusion                                                                                                                                                                                                                                                                                                                                                                     |

The shared changeCreatorComposerPositionAtom writes input placement and clears the trail override synchronously; the resolved atom supplies the matching default without an effect or duplicate mapping                                                        |

All ten layers were considered. Backend compilation, runtime session initialization, and transport payload inspection are inapplicable. Active conversations are outside this creation-layout preference.

The shared manual-layout regression changes one store value with Work Item and Project layouts mounted together, verifies persistence under the existing key, asserts the same textarea nodes and edited values through Bottom -> Middle -> Bottom, and verifies fill-sized agent frames do not add a second centering layer. Trail tests cover live default changes, resetting saved overrides in both layout directions, persisting the new layout/default across hydration, reselecting the current layout without erasing a later override, saved Middle hydration, saved overrides, malformed persisted values, and unchanged title/description nodes and skills/actions above the input while both manual creators change input/trail settings. Removing the trail storage key restores the layout-derived default; removing the input key restores Bottom. No historical data cleanup or migration is required.

Direct desktop geometry, SideChat/Compare-runners switching, and every form's visual state remain unmeasured because Computer Use was not authorized. Existing oversized files and unrelated workspace changes were not refactored.

The header is the only production writer of input placement, and it uses the linked state action. Targeted source search found the raw input atom written only inside that action. Existing storage keys and value formats are unchanged; the trail override key is removed only on an actual layout change. No historical user preference is cleared on startup.

Suggestion parity: ChatPanelStartPage reads the same input preference as SessionCreator to choose utility-action presentation; the creator chooses the matching grid and Solve Work Item trigger. Middle renders one footer row outside the input stack and preserves the existing add/create-work-item control in the skills row. The footer is not mounted for multi-runner content or creators without existing suggestions. The subsequent WorkItemPickerModal refactor gives both card and pill triggers the same reusable modal and removes the expanded composer-picker flag. The input ancestry remains unchanged; direct whole-view geometry is not measured.

Follow-up: the user requested removing the Add work item button above the input. The shared creator view no longer renders that control, and its unused onCreateWorkItem callback plumbing is removed through the creator slot contract and ChatPanelEmptyContent. Header/sidebar Work Item creation and the Solve Work Item modal remain unchanged. The latest Middle glow setting is 12px without focus expansion; it uses the same position attribute in Agent and Manual layout owners and adds no state or subscriptions.
