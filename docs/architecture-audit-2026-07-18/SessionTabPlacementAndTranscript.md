# Session tab placement and raw transcript architecture audit

Scope: bidirectional session-tab movement between Chat Panel and My Workstation, live session ownership, imported-session continuation, and raw transcript loading for ORGII/ORG2 and external history sources.

## Outcome

One session now has one visible tab owner at a time. Moving a tab changes only presentation state: it does not copy the session, recreate its EventStore, or introduce another send path. My Workstation renders the same `ChatView` as a secondary live surface, so an in-flight response remains streamable and the composer remains usable. If an immutable external or teammate-imported session forks on its first continued message, the owning pill is retargeted in place to the new writable ORGII session.

The same ownership boundary now also accepts sidebar entry points. A local, ORG2-owned, or externally loaded session row can be dragged onto the Workstation tab bar or opened through the native **Open in My Station** context-menu action. Both paths remove any matching Chat Panel owner and open/focus the canonical keyed Workstation tab. The Workstation header and Chat Panel pill consume one shared session-identity icon treatment.

Raw transcript loading follows the source boundary. External histories return their full unprojected source chunks; ORGII and ORG2 sessions merge durable EventStore rows with current in-memory rows, preferring the live version of an event with the same ID. The viewer is shared by both tab surfaces.

## Acceptance criteria

- A Chat Panel session can move to My Workstation by menu action or by dropping it on the Workstation tab bar.
- A supported sidebar session row can be dragged onto the Workstation tab bar, and its right-click menu exposes **Open in My Station**.
- Sidebar drag, sidebar context menu, and Chat Panel transfer converge on the same canonical open action and cannot create duplicate visible owners.
- A Workstation `chat-session` tab can move back by its native context menu or by dropping it on the Chat Panel tab bar.
- Transfer removes the source pill, focuses the destination pill, preserves the session ID, and claims the same session pipeline.
- A session that was already streaming continues through the existing EventStore/session channel; transfer does not restart or duplicate the request.
- Native ORGII, ORG2 teammate-imported, and external history sessions render and can be continued from My Workstation.
- Continuing an immutable imported history retargets the same owning pill to the writable fork instead of navigating an unrelated surface.
- Raw transcript viewing exposes full external source chunks or the complete durable-plus-live ORGII EventStore payload and supports refresh/copy.
- Invalid or stale transfer payloads are rejected without removing either tab.
- An active Workstation `chat-session` renders without the Code primary sidebar or secondary bottom/right panel, without overwriting the user's persisted panel preferences.
- The global 40px tab-header row keeps its sidebar toggle in place but disables it through `sidebarToggleDisabled`.
- The same 40px row displays the resolved session icon and current session name.
- Session-only chrome does not expose fallback Code search/testing actions or a bottom-panel toggle that cannot open a panel.

## Systematic sweep

- Traced Chat Panel menu, Chat Panel drag, Workstation context menu, and Workstation drag through the same typed placement atom.
- Traced regular sidebar rows and locally owned cloud rows through their existing `session://` drag payload, the shared reference-drag events, Workstation hit-testing, and the canonical open atom.
- Traced the new native sidebar context-menu action through route activation and the same canonical open atom used by sidebar drag.
- Audited post-drag pointer behavior and suppressed the navigation click synthesized after a completed reference drag, preserving the one-owner invariant.
- Traced native/ORG2 streaming from `ChatView secondary` through the existing active pipeline and EventStore; transfer itself has no send, restart, or event-copy call.
- Traced both imported continuation branches in `ChatView`: external history session creation and teammate-copy forking now retarget their owning surface through the same callback shape.
- Searched all `chat-session` factories/renderers to preserve the canonical keyed Workstation ID and work-item metadata during continuation.
- Searched external-history registrations and routed all supported external prefixes through `loadFullTranscriptChunks` rather than the projected chat history.
- Searched changed TSX files for repeated drag surfaces, drop-target styling, and transcript viewers; the overlay class, highlight class, drop hook, and dialog are shared.
- Traced every Workstation session chrome consumer: primary sidebar configuration, secondary panel configuration, sidebar header actions, bottom-panel toggle publication, and the active 40px header contribution now agree on `chat-session` behavior.
- Preserved panel preferences by deriving `collapsed`/`undefined` configurations from the active tab instead of writing the persisted sidebar or bottom-panel atoms.
- Replaced the two session-header icon implementations with `SessionIdentityIcon`, preserving Chat Panel's exact 16px/stroke treatment on both surfaces.

## Shared menu, formatting, and historical-turn loading extension

### Extension acceptance criteria

- Chat Panel and My Station render one shared session overflow menu with the same action order and presentation controls.
- Token usage, status bar, pagination, and compact/full display settings are persisted once and take effect in both surfaces immediately.
- The My Station session header exposes find, reload, move back, copy event JSON, raw transcript, link, optional cloud share, and export actions.
- My Station registers the same in-chat search callback, passes the shared compact/pagination values into `ChatView`, and mounts the same status bar when enabled.
- A historical-turn projection uses the version and session identity from the same global or session-scoped atom route that supplied its events.
- A scoped ORGII/ORG2 session can replace an `unloadedTurn` placeholder after the round-window merge without waiting for an unrelated global snapshot.
- Explicit merged-history overrides remain renderable, while stale events from a previous global session remain gated during a switch.
