# PR #610 Org Channels Follow-ups — Architecture Audit

**Date:** 2026-07-30

**Scope:** `origin/develop..fix/org-channels-audit-followups`, including the four items originally deferred in PR #610

**Verdict:** pass after fixes; no known P0/P1/P2 architecture finding remains in the audited scope

## Findings and disposition

| Priority | Boundary                   | Verdict  | Finding                                                                                                                                                            | Resolution                                                                                                                                                                                                                             |
| -------- | -------------------------- | -------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| P1       | Local message mutation     | fix      | Archiving disabled posting and drop, but old local messages could still be edited or deleted.                                                                      | `DiscussionChannelPanelView` now passes null edit/delete handlers for archived channels; row tests cover the read-only grouped case.                                                                                                   |
| P1       | Access lifecycle           | fix      | A cloud channel tab could remain open after private membership revocation or hard delete.                                                                          | The full active+archived listing now reconciles cloud tabs per org; absence closes only inaccessible tabs. Local hard deletes use the same lifecycle atom.                                                                             |
| P1       | Authoritative UI lifecycle | fix      | Dual-instance deletion could leave a channel-bound settings/members/archive/delete dialog open against a channel that no longer existed.                           | Channel-bound dialogs are now derived closed when their target is absent from the authoritative active+archived listing; org switches use the same rule.                                                                               |
| P1       | Local persistence          | fix      | Crash-era or interrupted-delete message rows had no boot-time owner reconciliation.                                                                                | A one-shot local registry reconciliation purges orphan rows and evicts their `atomFamily` entries.                                                                                                                                     |
| P1       | Local persistence          | fix      | Per-channel live-row quota did not bound total rows, total channels, or serialized localStorage bytes.                                                             | Added 500 live rows/channel, 2,000 rows/store, 1,000 channel rows, and a 4 MiB UTF-8 message-store budget with exact incremental byte accounting.                                                                                      |
| P2       | Feed actions               | fix      | Consecutive grouped messages suppressed their entire author header and therefore had no edit/delete controls.                                                      | Grouped rows now receive a corner action toolbar; focused tests cover writable and read-only states.                                                                                                                                   |
| P2       | Fetch ownership            | fix      | Multiple `useOrgChannels` consumers issued identical list RPCs and returned unstable partition arrays.                                                             | Identity/org/archive-keyed single-flight coalesces the list request, clears in `finally`, and memoizes active/archived partitions.                                                                                                     |
| P2       | Mutation invalidation      | fix      | Create/delete dialogs bumped the per-org listing version and their sidebar callbacks bumped it a second time.                                                      | Dialogs remain the sole mutation invalidation owner; dead callbacks and props were removed.                                                                                                                                            |
| P2       | Realtime diagnostics       | fix      | A lossy boolean status callback treated normal `CLOSED` teardown as a warning.                                                                                     | Consumer warnings were removed; the raw realtime client remains the owner for `CHANNEL_ERROR` and `TIMED_OUT` diagnostics.                                                                                                             |
| P2       | Focus recovery             | fix      | A visible-but-blurred instance could release its Realtime lease after the grace period and miss remote create/rename/delete signals until a visibility transition. | The authoritative listing now refetches on window focus regain as well as hidden-to-visible, while the existing identity/org single-flight coalesces consumers.                                                                        |
| P2       | Tab metadata               | fix      | Reconciliation closed inaccessible tabs but did not refresh a surviving tab's cached name or visibility after rename/archive transitions.                          | Reconciliation now consumes authoritative channel payloads, updates the tab title/payload in place, and still closes only absent channels.                                                                                             |
| P2       | UI duplication             | abstract | Eight real two-action dialog footers and both destructive confirmation bodies were duplicated.                                                                     | Added scope-neutral `ChannelDialogFooter` and `ChannelDeleteConfirmation` primitives. The ninth dialog is member management and has an inline add action, not a dialog footer, so it is intentionally not forced into the abstraction. |
| P2       | Naming ownership           | fix      | Bare `features/Channels` and cloud-owned validation helpers overloaded “channel” across unrelated domains.                                                         | Renamed the shared surface to `features/DiscussionChannels`, renamed the panel view, and moved validation/form contracts into that scope-neutral boundary.                                                                             |

## Ten-layer checklist

| Layer                              | Coverage                                                                                         | Result                                                                                                                                                                                                            |
| ---------------------------------- | ------------------------------------------------------------------------------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1. Domain model and invariants     | Local/cloud channel identity, archive semantics, post/edit/delete capability, quotas             | Pass. Archived local channels are read-only; cloud identity remains `(orgId, channelId)`; active and retained-state bounds are explicit.                                                                          |
| 2. Ownership and module boundaries | Shared contract, dialogs, listing invalidation, message/control planes                           | Pass. Scope-neutral UI/validation lives in `DiscussionChannels`; cloud RPC state remains in `Org2Cloud/channels`; local persistence remains in store atoms.                                                       |
| 3. State machines and transitions  | Listing phases, archive/unarchive/delete, dialog targets, edit/delete tombstones                 | Pass. Tab and dialog reconciliation runs only from an authoritative `ready` listing and includes archived rows, avoiding archive-as-revocation while closing revoked/deleted targets.                             |
| 4. Identity and cache keys         | Auth identity, org scope, archive flag, tab keys, atom families                                  | Pass. Single-flight uses identity+org+archive scope; cloud tab keys include org; purges evict channel selector families.                                                                                          |
| 5. Unknown/default behavior        | Realtime signal kinds and subscription statuses                                                  | Pass. Unknown db-change kinds retain coarse recovery; normal closed teardown is not misreported as failure.                                                                                                       |
| 6. Lifecycle symmetry              | Mount/unmount, focus/visibility, account/org switch, create/delete invalidation, purge/reconcile | Pass. Focus/visibility listeners unsubscribe on effect cleanup; in-flight entries clear in `finally`; account switching wipes visible state; deletion and boot recovery converge both control and message planes. |
| 7. Resource bounds                 | Rows, bytes, active/archived registry, repeated consumers                                        | Pass. Bounds are enforced before persistence; incremental byte accounting avoids a steady-state whole-store serialization loop.                                                                                   |
| 8. Wire/protocol parity            | Cloud RPC arguments, success handling, capability gating                                         | Pass. This PR changes no public wire shape. Existing request tests cover RPC payloads; archive/delete retain HTTP-success semantics from PR #610.                                                                 |
| 9. Entry-point parity              | Sidebar active/archived rows, open tabs, local/cloud dialogs                                     | Pass. Both sidebar scopes refresh surviving tab metadata, close inaccessible tabs and stale channel-bound dialogs, and share the matching dialog primitives.                                                      |
| 10. Resolver symmetry and naming   | Local/cloud shared contracts and seven “channel” meanings                                        | Pass with explicit terminology map below. External/runtime concepts keep their native names; the conversational feature no longer owns a bare global `Channels` namespace.                                        |

## “Channel” terminology map

| Meaning                          | Required name in ORGII code/docs                                                                   | Example boundary                                   |
| -------------------------------- | -------------------------------------------------------------------------------------------------- | -------------------------------------------------- |
| Team conversational room         | **discussion channel**; `DiscussionChannels`, `CloudChannel`, or `LocalChannel` when scope matters | `src/features/DiscussionChannels/`                 |
| Provider integration destination | **integration channel** or provider-specific name                                                  | Slack/Teams/Discord integration configuration      |
| Tauri typed event pipe           | **Tauri IPC channel** / `Channel<T>`                                                               | Rust/Tauri command signatures                      |
| Supabase live subscription       | **realtime subscription channel**                                                                  | `org2CloudRealtimeClient`                          |
| Model reasoning lane             | **thinking/reasoning channel**                                                                     | Chat rendering adapters and thinking-channel tests |
| Application update lane          | **release/update channel**                                                                         | updater stable/beta configuration                  |
| Browser scheduler primitive      | **MessageChannel scheduler**                                                                       | Web scheduling utilities                           |

Bare `Channel*` component names remain acceptable inside the now-explicit
`DiscussionChannels` module or a cloud/local namespace. Cross-domain helpers
must use the qualified terminology above.
