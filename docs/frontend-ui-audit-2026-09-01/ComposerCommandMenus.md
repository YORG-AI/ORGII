# Composer command menus UI audit

Scope: the shared `+` / `@` menu and the remaining `/` skills menu in the main chat input, session creator, and project/work-item composers.

| Line                                  | Element                   | Verdict          | Reason                                                                                                                                                                         | Suggested change                                                                                  |
| ------------------------------------- | ------------------------- | ---------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------- |
| `ContextMenu/index.tsx:67`            | Shared `+` / `@` surface  | abstract         | The two triggers require the same Upload row, mode rows, mention/context results, nested navigation, and keyboard contract across three composer hosts                         | Keep `ContextMenu` as the single results-only implementation                                      |
| `ContextMenu/index.tsx:90`            | Composer-owned search     | fix              | A search input inside the dropdown duplicates the composer, moves focus away from it, and makes `+` / typed `@` query ownership ambiguous                                      | Keep `searchQuery` read-only in the menu and derive it from the active inline composer trigger    |
| `ContextMenu/useContextMenu.ts:362`   | Keyboard navigation       | keep with reason | One flat active index is needed so Up/Down/Tab wrap consistently across Upload, modes, context rows, and live file results; Left/Escape retain nested-menu back/close behavior | None                                                                                              |
| `InputAreaPortals.tsx:74`             | `/` portal boundary       | fix              | Passing action/tool rows or mode/upload controls into `/` recreated the old mixed menu and could trigger work unrelated to skills                                              | Filter the slash portal to `category === "skill"` and keep mode/upload in the shared context menu |
| `SlashCommandPortal/useEntries.ts:18` | Skills-only slash entries | keep with reason | `/` has a distinct lazy skill-loading lifecycle and command-argument behavior, so sharing the `+` / `@` component would couple unrelated state                                 | Keep a separate, narrowed slash menu                                                              |
| `SlashCommandPortal/useEntries.ts:23` | Pinned skills section     | fix              | Hiding the quick-action bar removed the only visible projection of saved skill pins even though their persisted state remained valid                                           | Project matching pins first in `/`, in saved order, and deduplicate them from scope sections      |
| `SlashCommandPortal/MenuRows.tsx:54`  | Per-skill pin control     | keep with reason | The shared icon-only `Button` keeps the composer focused, exposes `aria-pressed`, and separates pinning from the row's insert action                                           | Keep the 24px icon-button hit area and retain Shift+Enter as its keyboard equivalent              |
| `ContextMenu/ResultItems.tsx:187`     | Trailing row action seam  | keep with reason | The shared menu row owns its layout and hover group, so a typed trailing slot avoids rebuilding the row shell in the slash menu                                                | Keep `trailingContent` optional; existing arrow-only consumers remain unchanged                   |
| `ProjectContentEditor/index.tsx:240`  | Project/work-item upload  | fix              | An outer callback-owned file input made manual `+` differ from typed `@` and duplicated upload ownership                                                                       | Keep the hidden input beside the shared portal so either trigger selects the same Upload action   |
| `ContextMenuPortal.tsx:102`           | Above-input frame         | keep with reason | Every host needs the same portal positioning, full anchor width, and 24px side inset while avoiding ancestor clipping                                                          | Continue using `INPUT_AREA_MENU_FRAME` through the shared portal                                  |

Verdict totals: **4 fix**, **5 keep with reason**, **1 abstract**.
