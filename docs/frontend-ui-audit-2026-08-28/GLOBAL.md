## Recommended order of attack

1. Consolidate the dropdown-search sweep; it has the broadest repeated UI surface and an existing component to extend.
2. Extract the shared Search/Replace text-field leaf, then cover input/textarea modes and keyboard navigation with focused tests.
3. Establish one CodeEditor file-content authority before attempting low-level field refactors; it removes duplicate I/O and dirty-state risk.
4. Consolidate numeric draft semantics and file-tree inline editing locally, with tests that lock down their intentionally different commit rules.
5. Extract field chrome/size tokens last. The three primitives have 179 direct import sites, making this a high-blast-radius refactor despite clear duplication.

Verdict totals: **5 fix candidates**, **4 abstract**, **3 keep with reason**, **1 watch**.
